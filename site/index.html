Missing evidence is itself evidence.

Cedulon is the open audit layer for agent payments. Every spend carries a signed receipt, and the receipts are reconciled against what the payment rail itself reports. A payment that left no receipt does not disappear from the books. It shows up as a finding.

npx -y @cedulon/mcp-server

Five MCP tools over stdio for Claude Desktop, Claude Code and Cursor. Nothing here moves money: the server settles on a mock rail and holds no wallet.

1Open the seal

One seal, four records

Pull the seal apart and each layer is a record of its own: the policy that decides, the rail's own extract, the signed receipt and the chain of receipts. Follow one payment of 0.25 USDC through all of them.

2Manifest

The seller signs the offer first

Before any money moves, the seller signs a trade manifest: what is sold, for how much, and a hash of the acceptance criteria. The receipt will carry the manifest's hash.

description            hourly forecast, 24 hours
amount                 0.25
currency               USDC
payee                  api.weather.example
acceptanceCriteriaHash c09d71e45b2f…
expiresAtMs            1793466000000
3Policy

Default deny

The policy decision point sees every request before the rail does. Over the limit, an unknown payee, a replayed nonce: refused, with the reason written down. If the policy engine is missing or throws, the answer is also no.

40.00 USDC              limit-amount
to unknown.example      scope-payee
engine unreachable      engine-unavailable
0.25 USDC to api.weather.example  allow
4Rail

The rail settles

The payment goes out on x402. Cedulon does not move the money. The settlement shows up in the rail's own extract, as one tick on the edge of the seal.

ref          0x9a3e51c8:1
amount       0.25 USDC
timestampMs  1793462400000
5Receipt

The receipt is signed

Payer, payee, amount, the policy hash, the manifest hash, the rail reference and the previous receipt's hash become one set of claims. They are encoded as deterministic CBOR and signed as COSE_Sign1. The pattern at the core is drawn from that receipt's SHA-256.

COSE_Sign1
protected  alg -19 (Ed25519)
           application/cedulon-receipt+cbor
payload    payer, payee, amount, currency,
           policyHash, manifestHash,
           x402PaymentRef, timestampMs, nonce,
           prevReceiptHash, outcome
signature  Ed25519
6Chain

Each receipt holds the one before

The new receipt carries the previous receipt's hash, so the chain shows when a receipt is changed or taken out. Every epoch closes with a checkpoint: how many receipts, their totals, the chain head and the previous checkpoint's hash.

prevReceiptHash  9f3a0c17e2b6…
checkpoint       epoch, receiptCount, totals,
                 chainHead, hash of the previous one
7Bypass

Someone skips Cedulon

A second payment of 7 USD goes straight to the rail. No manifest, no policy decision, no receipt. The rail settles it anyway, and Cedulon cannot stop that. But the rail writes it down.

ref      bypass-hidden
amount   7 USD
receipt  none
8Audit

The audit finds the empty place

Reconciliation walks the rail's extract and pairs every settlement with a receipt. The settlement with nothing to pair with is the finding. These lines are the repository's own bypass demo.

code    settlement-without-receipt
detail  settlement bypass-hidden 7 USD
        has no spend receipt
audit: 1 settlement without receipt → FAIL

The same audit works for decisions

A spend is one kind of effect. The decision profile applies the same reconciliation to a decision log: a signed allow, deny or defer on one side, and what the channel actually carried on the other.

A refusal followed by the effect it refused

A spend audit would call it a settlement without receipt. Here it is a finding with its own name.

effect-against-refusal → FAIL

The class of the effect is under the signature

An allow names what it allowed and what kind of thing it is. A row that carries the allowed hash under another class is a mismatch.

Run it on your machine

Point Claude Desktop, Claude Code or Cursor at the npm package. There is nothing to clone and nothing to build. The server makes no network requests.

{
  "mcpServers": {
    "cedulon": {
      "command": "npx",
      "args": ["-y", "@cedulon/mcp-server"]
    }
  }
}
claude mcp add cedulon -- npx -y @cedulon/mcp-server

Limits come from the environment, for example CEDULON_MAX_AMOUNT and CEDULON_ALLOWED_PAYEES. Set CEDULON_STATE_PATH to keep the receipt chain across restarts.

ToolWhat it does
cedulon_spendChecks the policy, then returns a signed receipt or a refusal with its reason.
cedulon_auditReconciles a rail extract against the receipt chain and returns findings and counts.

cedulon_statusVersion, active policy, receipt count and chain head.

Questions

What does Cedulon actually do?

Cedulon sits above payment rails such as x402 and AP2 as an audit layer. It writes a signed spend receipt, a chained epoch checkpoint, and a reconciliation of the rail extract. If a spend left no receipt, the gap is the finding. The design is specified in IETF Internet-Drafts and published as open source under Apache-2.0.

Can anyone verify a spend receipt?

A signed spend record checks as valid or tampered. That is the easy half. A spend that never issued a receipt leaves no object to verify, and the books can still look clean. The companion audit compares the rail extract to the receipt chain so a missing receipt becomes a finding.

Does Cedulon take custody of funds?

Cedulon does not take custody and does not operate escrow. An optional third-party escrow role may appear in the protocol as an interface. This repository uses mock keys and a mock rail. The published packages do not touch money: no real wallets and no network rails.

How do I attach Cedulon to Claude or Cursor?

The gated spend and extract audit are five MCP tools on stdio, published on npm as @cedulon/mcp-server. Point Claude Desktop, Claude Code, or Cursor at that package. There is nothing to clone or build. A five-minute path is in the repository Quickstart document.

What does Cedulon not prove?

Cedulon does not take custody and does not operate escrow. It does not judge delivery quality beyond a hash compare against the manifest acceptance criteria. Payment rails may succeed even if Cedulon is skipped. Production key storage is out of scope in this repository. Completeness checking does not replace prevention.
